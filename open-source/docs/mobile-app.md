# 共用手机 App

官方云与自托管共用同一套 App 界面、协议和业务实现。登录页选择服务器，登录后只绑定一个活动实例；不把两个实例的账号、聊天与本地存储混用。源码整理不是重写 App，也不迁移用户数据。

## 构建配置边界

公共 `open-source/config/app-profile.cjs` 默认自托管发行配置、关闭 OTA，不读取官方目录、不自动寻找可选私有模块。发行配置与登录页的服务器选择是两个边界：同一界面可选择官方云或自己的服务器，但登录后仅绑定一个实例。官方发行构建显式提供自己的身份和更新配置；缺失则失败，不静默降级为另一个发布渠道。

原生应用标识、签名团队、商店信息、关联域名和官方推送 / Apple 登录插件属于构建配置，不改变共用界面。公共基础配置不绑定官方签名团队；自行发行时必须使用自己的应用标识、证书和服务配置。兼容计数用于服务端最低构建版本门禁，不应随意重置为 1。公共服务端没有配置短信、语音或推送，不影响本地账号登录和站内消息；可用功能仍以实例能力与对应构建支持为准。

企业 OTA 默认关闭。启用自己的更新源必须配置 HTTPS 与自己的公钥证书；更换业务服务器不改变更新信任来源，详见 [企业 OTA](enterprise-ota.md)。

自托管连接默认不启动系统推送 SDK、不请求通知权限或上传设备推送 Token；站内消息和未读不受影响。明确需要推送时，先在服务端配置供应商与 `SHENNIAN_PUSH_MODE=providers`，并在自行构建 App 时设置 `EXPO_PUBLIC_SHENNIAN_PUSH_MODE=providers`、自己的供应商项目与原生凭据。设置为 `off` 可显式关闭；未知值按关闭处理。单模型最小部署无需这些配置。

## 源码与构建

仓库保留 `packages/app` 与 `open-source` 相对布局；App 界面、业务实现、原生模块和移动测试均使用同一份源码。不需要官方工程、官方签名、EAS 账号或私有模块才能生成原生项目。

在完整仓库根执行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test:app
pnpm build:app
# macOS，安装 Xcode / CocoaPods 后
pnpm ios
# 安装 Android Studio / SDK 后
pnpm android
```

首次运行 Expo 会从公共配置创建原生工程。iOS 真机发行需要自己的 Apple 开发团队与签名，Android 发行需要自己的 keystore；不要将这些凭据提交进仓库。模拟器编译不需要官方签名。公共构建默认应用标识为 `net.shennian.community`。

登录页切换到「自托管服务器」，填写部署时配置的 HTTPS origin（含自定义端口），再按实例策略注册或登录。自签 CA 必须先加入测试设备的信任链，不关闭 TLS 校验。Client 也连接同一服务器，不能把官方配对凭据复制到另一个实例。

未配置官方商店 / 联系群元数据时不展示评论入口，也不把组织的联系操作静默转到官方群。组织自己的联系配置由本实例服务提供。构建、API 链路与原生界面验收分别记录在[验收矩阵](self-hosted-acceptance.md)，不能以类型检查代替真机验收。Desktop 与其历史 IPC 集成测试不在移动发行范围；移动 transport 有不依赖 Desktop 的独立合约测试。
